Pago agrupado de obligaciones fiscales

El pago agrupado (bundle) le permite pagar múltiples obligaciones fiscales de su empresa en una sola transacción, repartida automáticamente entre las entidades emisoras (Tesoro Público, Ayuntamiento, Cámara de Comercio). Optimiza el tiempo administrativo y reduce las comisiones bancarias.

Para: Empresa
En esta página

1. Concepto y ventajas

Una empresa típica tiene varias obligaciones fiscales anuales : CMF (Tesoro), Tasa Municipal (Ayuntamiento), Cuota Cámara (Cámara de Comercio), Licencia comercial, Certificados de Comercio, etc. En lugar de pagar cada una por separado (varias visitas, múltiples comisiones), el bundle permite agruparlas.

Ventajas

  • Una sola transacción bancaria — reducción de comisiones
  • Reparto automático entre las 3 entidades emisoras (sin manipulación de su parte)
  • Solicitud única LIC-2026-XXXXX con seguimiento centralizado
  • 3 recibos automáticos generados (uno por entidad: REC para Tesoro, REC para Ayuntamiento, REC para Cámara)
  • Selección flexible — pague solo las obligaciones que desea, las demás quedan pendientes

2. Wizard 4 etapas

El wizard del bundle se accede desde Mis empresas → botón «Pagar Obligaciones» en una empresa. Comprende 4 etapas:

Etapa 1/4 — Identificación de la empresa

Buscar o seleccionar la empresa concernida. Si tiene varias empresas, se muestran como cards con búsqueda por NIF, PE-XXXX o nombre.

Etapa 2/4 — Selección de obligaciones (Modo A vs B)

La pantalla muestra todas las obligaciones fiscales 2026 de la empresa, agrupadas por entidad. Antes de seleccionar, escoja el modo:

  • Modo A — Por línea : seleccione individualmente cada obligación que quiere pagar (con checkbox)
  • Modo B — Pago consolidado : pago único de TODAS las obligaciones en una sola transacción

Etapa 3/4 — Pago

Pantalla de pago con resumen de las obligaciones seleccionadas, total a pagar, y selector del método de pago (Mobile Money, efectivo en agencia, transferencia, tarjeta, cheque). Mismo flujo que el wizard estándar.

Etapa 4/4 — Confirmación

Pantalla final con check verde, número de referencia LIC-2026-XXXXX, monto total, número de obligaciones cubiertas, modo elegido, y los próximos pasos (validación 1-3 días, procesamiento, recepción licencia por email).

3. Modo A vs Modo B — comparación detallada

Consejo

Use el Modo A si quiere pagar prioritariamente las obligaciones más urgentes (próxima a vencer) o si su flujo de caja no permite pagar todo. Use el Modo B si tiene fondos disponibles para finalizar todas las obligaciones de un golpe (más rápido, menos comisiones).

4. Confirmación y seguimiento

Después del pago, su solicitud LIC-2026-XXXXX aparece en Mis solicitudes con un stepper visual y 3 sub-tarjetas (una por entidad emisora) mostrando el estado individual de cada validación.

Cada entidad valida su parte por separado : Ayuntamiento puede validar antes que la Cámara, etc. Por lo tanto, recibirá 3 emails progresivos con el recibo correspondiente cada vez que una entidad valida.

5. Lock ordering técnico (info técnica)

Información técnica (avanzado)

Esta sección es informativa para los curiosos. No necesita comprenderla para usar la función.

El bundle implementa una lógica transaccional multi-tabla con lock ordering canónico para evitar deadlocks cuando 100+ agentes simultáneos validan operaciones similares. El orden estricto:

┌─────────────────────────────────────────────────────────────────┐
│  ORDEN DE LOCK CANÓNICO PARA BUNDLE PAYMENT                     │
│  (a respetar siempre para evitar deadlocks)                     │
└─────────────────────────────────────────────────────────────────┘

   1. commercial_licenses        ← SELECT FOR UPDATE (lock racine)
              │
              │  Lock obtenido — la licencia comercial se reserva
              ▼
   2. service_requests           ← INSERT (sin FOR UPDATE)
              │                    Concurrencia gestionada por
              │                    índice único partial idx_sr_commercial_license_unique
              │
              ▼
   3. license_obligations        ← UPDATE batch (locks auto)
              │                    Las obligaciones se marcan
              │                    pagadas o pendientes
              │
              ▼
   4. service_payments           ← INSERT final
              │                    Registra el pago efectivo
              │
              ▼
   ✅ Commit transaction         (todo o nada — atómico)

   Configuración de la transacción:
       SET LOCAL lock_timeout = '3s';
       SET LOCAL statement_timeout = '5s';

   En caso de UniqueViolationError sobre service_requests:
       deterministic SELECT por commercial_license_id (no retry)

Este diseño asegura que 1000+ pagos simultáneos sobre la misma empresa nunca terminen en deadlock. La latencia de bloqueo está limitada a 3 segundos máximo para no penalizar la experiencia usuario.

Bien hecho

El bundle es la opción recomendada para empresas con varias obligaciones. Centraliza el seguimiento y reduce el tiempo administrativo.
