Audit Logs : trazabilidad completa y conservación 7 años

Toda acción sensible en Facil (login, decisión agente, modificación de configuración, acceso a datos personales, validación de pago) está registrada en un audit log dedicado. La retención legal es de 7 años (obligación de archivo administrativo en Guinea Ecuatorial) y la integridad está garantizada por una cadena de hash inalterable. Solo el rol Admin tiene acceso completo al log; los supervisores ven los logs de su entidad; los agentes ven sus propios logs.

1. Schema de las entradas (7 columnas obligatorias)

Columna Tipo Descripción
idUUIDIdentificador único de la entrada
timestampTIMESTAMPTZ UTCFecha + hora precisa al milisegundo, en UTC
actor_emailTEXTEmail del usuario que realizó la acción (o «system» para acciones automáticas)
actionTEXT (enum)Tipo de acción : login, logout, approve, reject, escalate, role_change, config_update, etc.
entity_type + entity_idTEXT + UUIDObjeto modificado : service_request, user, payment, role, config_key, etc.
before / afterJSONBSnapshot antes y después de la modificación (para acciones de update)
ip_address + user_agentINET + TEXTPara trazabilidad técnica y detección de uso fraudulento (IP no habitual)

2. Cadena de hash : integridad infalsificable

Cada entrada del log lleva un campo adicional chain_hash calculado como : SHA-256(prev_chain_hash || row_data). La primera entrada usa un hash de génesis. Esta cadena garantiza la integridad : si una entrada es modificada o suprimida posteriormente, todas las entradas siguientes tienen un hash incoherente, lo que se detecta automáticamente.

┌─────────────────────────────────────────────────────────────────┐
│ Cadena de hash de los audit logs                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Entrada 1 :                                                    │
│   prev_chain_hash = GENESIS                                     │
│   chain_hash = SHA256(GENESIS || timestamp:..., actor:..., ...) │
│                                                                 │
│  Entrada 2 :                                                    │
│   prev_chain_hash = chain_hash[1]                                │
│   chain_hash = SHA256(chain_hash[1] || timestamp:..., ...)      │
│                                                                 │
│  Entrada N :                                                    │
│   prev_chain_hash = chain_hash[N-1]                              │
│   chain_hash = SHA256(chain_hash[N-1] || timestamp:..., ...)    │
│                                                                 │
│  Verificación :                                                  │
│   • Recalcular toda la cadena desde GENESIS                     │
│   • Comparar con los chain_hash almacenados                     │
│   • Discrepancia = entrada manipulada (con índice exacto)       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

3. Búsqueda y filtrado

La interfaz admin propone una pantalla de búsqueda con los filtros siguientes :

  • Período — hoy / esta semana / este mes / personalizado (rango de fechas)
  • Actor — email exacto o pattern (ej. *@dgi.gov.gq)
  • Acción — drop-down con todas las acciones disponibles
  • Tipo de entidad — service_request / user / payment / etc.
  • IP — dirección exacta o subred CIDR
  • Búsqueda libre — full-text sobre before/after JSONB (usa GIN index PostgreSQL)

4. Alertas automáticas configurables

El admin puede definir reglas de alerta sobre patrones detectados en el log. Ejemplos típicos :

Pattern Trigger Acción
Login fallido repetido > 10 fallos en 10 min sobre la misma cuenta Bloqueo temporal + email admin
Login geo anormal IP de otro país que la habitual Push usuario + email admin + 2FA forzada
Rechazos en bloque Un agente rechaza > 10 solicitudes en 1h con el mismo motivo Email supervisor para auditoría
Importe sospechoso Validación de pago > 5M XAF por un mismo agente en una jornada Email director Tesoro + obligación reporting hebdomadario
Modificación config crítica Cambio role admin, modificación workflow_engine, suppression endpoint Email todos los admin + log doble (en log + en table dedicada)

5. Export y conformidad RGPD

Ciudadanos y empresas pueden solicitar (en virtud del derecho de acceso) un export de las acciones que les conciernen. El admin tramita la solicitud desde la pantalla Audit Logs con el filtro «entity_id = [identificador del solicitante]». El export se genera en formato JSON estructurado + PDF lisible. Plazo máximo: 30 días (obligación legal). El export queda registrado en el log lui-même (méta-action : data_access_request).

6. Retención : 7 años + archivado

Las entradas activas se mantienen en la BD principal durante 12 meses (acceso rápido para auditoría operacional). Después de 12 meses, las entradas son archivadas en cold storage (Google Cloud Storage, encriptado AES-256, con replicación geográfica). El acceso a los archivos requiere una solicitud al equipo técnico (delay típico : 24-48h). La duración total de retención es de 7 años desde la fecha de la acción. Después de 7 años, las entradas son destruidas con una opération auditable (méta-entry «retention_purge»).
