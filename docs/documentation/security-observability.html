Security Observability — IP / device / geo + prompt injection

Per-request HTTP telemetry (IPs, devices, geolocation, suspicious patterns) + prompt injection detection persisted to BD for SQL queryability + Grafana dashboard with 20 panels + 3 security alert rules. Closes the gap from Phase B.5 where injection detection was log-only. Privacy-safe (RGPD): IPs retained 30 days raw, aggregations preserved indefinitely via materialized view.

1. Why & gap analysis #

User questions 2026-05-05: "prompt injection detection est-ce un dashboard ou une métriques ?" + "controler les différentes adresses ip qui se connecte et leur requetes avec filtré par type de devices". Phase B.5 had implemented injection DETECTION but only logged to OTEL spans (Tempo, 14d retention). No SQL queryability, no dashboard, no alerts on trends. Phase C closes both gaps.

2. Stack architecture #

HTTP request
  └─ RequestTelemetryMiddleware (pure ASGI, ~200ns excluded paths)
       ├─ extract: method/path/status/latency/IP/UA/referer/trace_id
       ├─ enrich: parse_ua() → device_type / browser / OS
       ├─ enrich: lookup_ip() → country / city / lat/lon
       ├─ sample: errors 100% / new IP 100% / bot 1% / steady 10%
       └─ asyncio.create_task(_persist_request) → request_telemetry table

Cron every 6h:
  └─ DELETE rows > 30d + REFRESH MATERIALIZED VIEW CONCURRENTLY hourly

3. BD schema #

Mig 328 — extends ai_call_metrics

  • injection_risk text (none/low/medium/high)
  • injection_score int (0..100+)
  • injection_rules text[] (top 5 matched)
  • Partial index idx_aim_high_risk WHERE risk IN (medium, high)

Mig 329 — request_telemetry table

31 columns / 9 indexes / 7 CHECK constraints / 1 hourly MV. Key columns: ip_address inet, device_type, browser_name, os_name, geo_country, geo_lat/lon, sampled_pct, is_suspicious, suspicious_reasons text[].

Mig 330 — register security-monitoring dashboard

12th dashboard in dashboard_registrations: UID facil-security-monitoring, category=security, rls_mode=admin_only, display_order=95.

4. Capture middleware (sampling) #

app/core/request_telemetry_middleware.py — pure ASGI (NOT BaseHTTPMiddleware which would consume the request body). Decision tree per request:

  1. Excluded path (healthz / static / metrics / docs) → bypass entirely
  2. status >= 400 → sample 100%
  3. New IP / new user in last 1h (LRU 10K cap) → sample 100%
  4. Bot detected (UA → is_bot=true) → sample 1%
  5. Steady-state success → sample 10%

sampled_pct stored on each row → aggregations multiply by 100 / sampled_pct for accurate counts. Persistence is fire-and-forget via asyncio.create_task — never blocks the response. Tracked WeakSet flushed at shutdown (5s timeout).

5. UA parsing & device classification #

app/core/user_agent_parser.py wraps the user-agents Python lib with @lru_cache(4096). UA strings are extremely repetitive in real traffic — expected hit rate ~99% → 200ns cached vs 30-50µs uncached. Soft-import: returns all-NULL when lib missing.

Device type derivation order: bot > mobile > tablet > desktop > unknown. Bot detection is the lib's responsibility (uses regex against thousands of known bot UAs).

6. GeoIP enrichment (MaxMind) #

app/core/geoip.py wraps geoip2 Python lib over the offline GeoLite2-City.mmdb file. Fully offline — IPs never leave the backend. Free of rate-limits (vs ip-api.com online). LRU 4096 cached.

Private/loopback IPs (127.x, 10.x, 192.168.x, 172.16-31.x, 169.254.x, IPv6 ::1, fe80:, fc00:) are short-circuited to NULL without hitting the reader.

Setup

  1. Sign up free at maxmind.com/en/geolite2/signup
  2. Download GeoLite2-City.mmdb (~80 MB) → upload to /tmp/GeoLite2-City.mmdb on Cloud Run boot OR bundle in container
  3. Set MAXMIND_LICENSE_KEY in Secret Manager (rotation 12 mois)
  4. Override path with GEOIP_DB_PATH env var if non-default

7. Dashboard #

UID facil-security-monitoring, 20 panels in 5 row sections. Listed at /admin/dashboards under category security (rls_mode=admin_only). Variables: device_type, country, user_role (multi-select with All).

  • 📊 Overview: total requests, unique IPs, error rate %, bot share %, suspicious count (5 stats)
  • 🌍 Geographic: top 10 countries bar chart, top 5 countries time series
  • 📱 Device & browser: device donut, top browser × OS, device rate stacked area
  • 🚦 IPs & users: top 20 IPs (count/errors/last seen), new IPs per hour
  • 🔥 Errors & security: top 4xx paths, failed logins by IP, AI injection trend (cross-link with ai-observability)

8. Alerts & runbooks #

RuleThresholdSeverity
facil-security-ip-spike1 IP > 1000 req / 5mincritical
facil-security-failed-login1 IP > 10 failed logins / 5mincritical
facil-security-bot-sharebot_share > 50% sustained 30minwarning

Runbook — IP request spike

1. Open dashboard, drill "Top 20 IPs by request count". 2. Identify the offending IP. 3. Check geo + device — if cluster of bots from same country, suspect coordinated attack. 4. Block via Cloud Armor / Cloudflare WAF / iptables. 5. Document in audit_logs with action='security.ip_blocked'.

Runbook — Failed login burst

1. "Failed logins by IP" panel → identify top IP. 2. Check if the user_email being targeted exists (BD lookup) — if yes, force password reset + 2FA enrollment. 3. Block IP. 4. If sustained → enable CAPTCHA on /login or temporary 2FA-mandatory mode.

Runbook — Bot share >50%

1. "Top browser × OS" panel → identify the dominant bot UA. 2. Either legitimate scraper (search engine, archive.org) → whitelist the UA, or vulnerability scanner → block. 3. Verify robots.txt served correctly.

9. Privacy & retention (RGPD) #

  • Legal basis: legitimate interest — security monitoring (Art. 6.1.f GDPR)
  • Retention: raw rows 30 days max (cron auto-delete). MV aggregations 90 days (no IP, just country/device counts).
  • FK: user_id ON DELETE SET NULL — user deletion clears the link
  • GeoIP fully offline: IPs never leave our backend (vs ip-api.com cloud)
  • No PII in MV: aggregations dropped IP/UA/path → safe long-term storage
  • RLS: dashboard rls_mode='admin_only' — non-admin users do not see IP data
