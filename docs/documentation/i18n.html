Internationalization Guide

Facil is fully trilingual: Spanish (primary), French, and English. The i18n system spans the frontend (11,400+ keys per locale), backend (entity translations + error messages), mobile apps, and communication templates.

Frontend i18n (next-intl) #

Architecture

The frontend uses next-intl with Next.js App Router's [locale] segment. All pages are nested under /[locale]/ which automatically detects and sets the language. 

packages/web/src/
├── app/
│   └── [locale]/              # Dynamic locale segment (es/fr/en)
│       ├── (auth)/            # Auth pages (login, register)
│       ├── (dashboard)/       # Protected pages
│       └── (public)/          # Public pages
├── i18n/
│   ├── messages/
│   │   ├── es.json            # Spanish (11,400+ keys)
│   │   ├── fr.json            # French
│   │   └── en.json            # English
│   ├── request.ts             # Server-side locale resolution
│   └── routing.ts             # Locale routing config

Usage in Components

import { useTranslations } from 'next-intl';

export function ServiceCard() {
  const t = useTranslations('services');

  return (
    <div>
      <h2>{t('catalog.title')}</h2>
      <p>{t('catalog.description')}</p>
      <span>{t('catalog.count', { count: 873 })}</span>
    </div>
  );
}

Backend i18n #

Language Detection Middleware

The language_middleware detects the user's language from the Accept-Language header and stores it in request.state.language for use throughout the request lifecycle.

Error Message Translation

Error messages are auto-translated based on the detected language. The TranslatedException class carries an error_code which maps to trilingual messages. Pattern matching handles legacy HTTP exceptions. 

# Error code mapping (app/core/errors.py)
class ErrorCode(Enum):
    NOT_FOUND = "ERR_NOT_FOUND"
    UNAUTHORIZED = "ERR_UNAUTHORIZED"
    SERVER_ERROR = "ERR_SERVER_ERROR"

# Each code has translations for es, fr, en
get_error_message(ErrorCode.NOT_FOUND, "fr")
# Returns: "Ressource non trouvee"

Database Translations #

Two Translation Tables

TablePurposeStorage Model
translations Unified translations for ENUMs, UI labels, form fields, system messages Key-value with locale column
entity_translations Entity-specific translations (ministry names, service names, etc.) Optimized structure (40% storage reduction vs. inline columns)

Database Content Convention

Spanish in Database, Translated at Runtime

All database content (ministry names, service names, categories) is stored in Spanish (the primary language). French and English translations are stored in the entity_translations table and resolved at query time.

Entity Translation Pattern

-- Entity translation lookup
SELECT
  m.name_es,
  COALESCE(et.translated_value, m.name_es) AS name_display
FROM ministries m
LEFT JOIN entity_translations et
  ON et.entity_type = 'ministry'
  AND et.entity_id = m.id::text
  AND et.field_name = 'name'
  AND et.locale = $1  -- 'fr' or 'en'

Translation Cache

Translations are cached for 1 hour via get_translations_cache() to minimize database queries. Cache invalidation is triggered when translations are updated via the admin API.

Mobile i18n #

Both mobile apps (Facil citizen and Facil Inspector) support the same 3 languages. Translations are stored as JSON files bundled with the app and loaded at runtime based on the user's language preference.

Communication Templates #

Email, SMS, push notification, and in-app notification templates are stored in their respective tables (email_templates, sms_templates, push_templates, notification_templates) with content for all 3 languages.

Adding New Keys #

To add a new translation key:

  1. Add the key to all 3 JSON files (es.json, fr.json, en.json)
  2. Follow the existing hierarchical structure: module.section.key
  3. Provide real translations (not machine-translated placeholders)
  4. Use the key in your component with useTranslations('module')
  5. For parameterized strings, use ICU message format: "count": "{count} servicios"

Translation API Endpoints

GET /api/v1/translations List translations by category/locale
POST /api/v1/translations Create new translation entry
PUT /api/v1/translations/{id} Update translation
GET /api/v1/entity-translations/{type}/{id} Get entity translations
GET /api/v1/frontend-translations/{locale} Bulk fetch for frontend hydration
GET /api/v1/enums/{enum_name}/values Get enum values with translations
